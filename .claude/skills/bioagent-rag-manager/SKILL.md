# 🧬 BioAgent RAG Manager

Скилл для управления базой знаний проекта `bioagent-ngs`. База знаний — это сердце агента: именно она позволяет не галлюцинировать параметры утилит и давать точные ответы по cfDNA/NGS.

## 📂 Структура проекта

```
bioagent-ngs/
├── docs/                    # Исходные markdown-документы
│   ├── gatk_mutect2_reference.md
│   ├── fgbio_umi_best_practices.md
│   ├── cfdna_fragmentomics_guidelines.md
│   └── ...
├── data/
│   ├── knowledge_base.jsonl # Чанки с метаданными
│   ├── faiss.index          # FAISS-индекс
│   └── faiss.index.chunks   # Метаданные чанков
├── scripts/
│   └── ingest_docs.py       # Скрипт парсинга docs/ → JSONL
└── rag_engine.py            # Класс RAGEngine
```

## 🎯 Команды скилла

### 1. `add-doc` — добавить новый документ в базу

**Когда использовать:** пользователь прислал статью, документацию утилиты, гайдлайн или свои заметки и хочет, чтобы агент их "запомнил".

**Алгоритм:**
1. Определить **категорию** документа:
   - `tool_reference` — точные параметры утилиты (GATK, fgbio, bwa-mem2, ichorCNA, LoFreq, SiNVICT)
   - `best_practices` — гайдлайны и рекомендации (GATK Best Practices, cfDNA-специфика)
   - `code_examples` — проверенные сниппеты (Snakemake rules, Python/R функции)
   - `troubleshooting` — частые проблемы и их решения
2. Определить **имя утилиты** (`tool_name`), если документ про конкретный инструмент. Иначе — `general`.
3. Сохранить markdown-файл в `docs/` с именем в формате `<tool>_<topic>.md` (например, `gatk_pon_creation.md`, `cfdna_oxidation_artifacts.md`).
4. Запустить переиндексацию: `python scripts/ingest_docs.py`
5. Показать пользователю статистику: сколько чанков добавлено, в какую категорию попали.

**Пример:**
```
Пользователь: Добавь в базу гайдлайн по созданию Panel of Normals для cfDNA
Агент: 
  ✅ Создан файл docs/gatk_pon_cfdna.md
  ✅ Категория: best_practices
  ✅ Инструмент: gatk
  ✅ Добавлено 7 чанков в базу знаний
  ✅ FAISS индекс пересобран (всего чанков: 854)
```

### 2. `rebuild-index` — пересобрать FAISS-индекс

**Когда использовать:** после ручного редактирования `docs/`, после `add-doc`, или если индекс повреждён.

**Команда:**
```bash
rm -f data/faiss.index data/faiss.index.chunks
python scripts/ingest_docs.py
```

**Важно:** операция использует OpenAI embeddings API — будет расход. Предупреди пользователя.

### 3. `search` — найти чанки по запросу

**Когда использовать:** пользователь хочет проверить, что уже есть в базе по какой-то теме, или отладить retrieval.

**Алгоритм:**
1. Использовать `RAGEngine.retrieve_relevant_context(query, top_k=5)`.
2. Показать каждый чанк с метаданными: `source`, `category`, `tool_name`, `relevance_score`.
3. Если пользователь указал фильтр (категория/инструмент) — применить его.

**Пример вывода:**
```
🔍 Найдено 5 чанков по запросу "UMI deduplication fgbio":

[1] score: 0.89 | source: fgbio_umi_best_practices.md | category: best_practices | tool: fgbio
    > Используйте стратегию adjacency для UMI длиной 8-12 bp...

[2] score: 0.82 | source: fgbio_umi_reference.md | category: tool_reference | tool: fgbio
    > GroupReadsByUmi --strategy adjacency --edits 1 --min-input-base-quality 20...

...
```

### 4. `stats` — статистика базы знаний

**Когда использовать:** пользователь хочет понять, что есть в базе, или проверить баланс категорий.

**Вывод:**
```
📊 Статистика базы знаний BioAgent:
- Всего чанков: 847
- Всего документов: 15
- Категории:
  • tool_reference: 312 (36.8%)
  • best_practices: 245 (28.9%)
  • code_examples: 178 (21.0%)
  • troubleshooting: 112 (13.2%)
- Топ-5 инструментов:
  • gatk: 198 чанков
  • fgbio: 142 чанка
  • bwa-mem2: 87 чанков
  • ichorcna: 64 чанка
  • samtools: 51 чанок
- Размер FAISS индекса: 147 MB
```

### 5. `eval-retrieval` — оценить качество retrieval

**Когда использовать:** после добавления новых документов или изменения chunking-стратегии, чтобы проверить, что retrieval работает корректно.

**Алгоритм:**
1. Использовать набор из 10-15 тестовых запросов с известными ожидаемыми источниками (хранятся в `tests/test_queries.json`).
2. Для каждого запроса вызвать `retrieve_relevant_context(top_k=5)`.
3. Посчитать метрики:
   - **Recall@5** — доля запросов, где ожидаемый источник попал в топ-5
   - **MRR** (Mean Reciprocal Rank) — средняя обратная ранговая позиция первого правильного источника
   - **Категориальная точность** — совпадает ли категория найденного чанка с ожидаемой
4. Вывести отчёт с примерами провалов (где retrieval ошибся).

**Пример вывода:**
```
🧪 Оценка retrieval (15 тестовых запросов):
- Recall@5: 0.93 (14/15)
- MRR: 0.81
- Категориальная точность: 0.87

❌ Провал:
  Запрос: "как настроить tumourPurity в ichorCNA для cfDNA"
  Ожидался: cfdna_fragmentomics_guidelines.md (best_practices)
  Получен: gatk_mutect2_reference.md (tool_reference)
  → Рекомендация: добавить больше чанков про ichorCNA в категорию best_practices
```

### 6. `export` / `import` — экспорт/импорт базы знаний

**Когда использовать:** для бэкапа, переноса между машинами, или шарения базы с коллегами.

**Команды:**
```bash
# Экспорт
tar -czf rag-backup-$(date +%Y%m%d).tar.gz \
    data/knowledge_base.jsonl \
    data/faiss.index \
    data/faiss.index.chunks \
    docs/

# Импорт
tar -xzf rag-backup-YYYYMMDD.tar.gz
```

## 📝 Формат новых документов

Чтобы скилл корректно обрабатывал новые документы, они должны следовать формату:

```markdown
# <Название документа>

## Описание
Краткое описание, для чего этот документ.

## Основная информация
...

## Параметры / Примеры / Решения
(в зависимости от категории)

## Связанные инструменты
- gatk
- fgbio

## Источники
- [GATK Documentation](https://...)
- [Статья](https://...)
```

## ⚠️ Ограничения и предупреждения

1. **OpenAI API расход** — переиндексация 1000 чанков ≈ $0.01-0.02. Предупреждай пользователя перед `rebuild-index`.
2. **Размер чанков** — текущая стратегия: 1000 токенов с перекрытием 200. Не меняй без пересмотра `eval-retrieval`.
3. **Категоризация** — автоматическая по имени файла. Если документ попадает не в ту категорию, переименуй файл (добавь `reference`, `best_practices`, `example` или `troubleshoot` в имя).
4. **Дубликаты** — перед `add-doc` проверь через `search`, нет ли уже похожих чанков в базе. Иначе будет шум в retrieval.

## 🔗 Связанные файлы проекта

- `scripts/ingest_docs.py` — основной скрипт парсинга
- `rag_engine.py` — класс `RAGEngine` с методами `retrieve_relevant_context`
- `docs/` — исходные markdown-документы
- `data/` — артефакты (JSONL, FAISS индекс)
- `tests/test_queries.json` — тестовые запросы для `eval-retrieval`

## 💡 Советы по развитию базы

1. **Добавляй troubleshooting-документы** — они дают максимальный ROI, потому что решают реальные боли пользователей.
2. **Держи tool_reference в актуальном состоянии** — версии утилит меняются, параметры устаревают. Раз в квартал проверяй `gatk_*`, `fgbio_*` документы.
3. **Пиши code_examples с контекстом** — не просто код, а "когда использовать" и "подводные камни". Это сильно улучшает качество ответов агента.
4. **Используй `eval-retrieval`** после каждого значимого добавления — чтобы убедиться, что новые документы не "задавили" старые полезные чанки.
