# Архитектура промптов и RAG-схемы

Документ описывает устройство ИИ-куратора курса «Практический Python».  
Эквивалент можно перенести в Google Docs / Notion без изменений структуры.

## 1. Роль и стиль

| Параметр | Значение |
|----------|----------|
| Роль | ИИ-куратор / наставник |
| Тон | Поддерживающий, конкретный, без снисходительности |
| Цель | Ориентация в материалах, орг. вопросы, персональные рекомендации |

## 2. Ограничения (guardrails)

1. **Не выставляет оценки** и не обещает баллы.
2. **Не меняет расписание** и дедлайны.
3. **Всегда ссылается на источник** (лекция / методичка / FAQ / LMS).
4. При отсутствии данных — честно говорит об этом и направляет к преподавателю / офис-часам.

Реализовано в системном промпте `src/prompts.py` (`SYSTEM_PROMPT`).

## 3. Сценарии ответов

| Код | Название | Поведение |
|-----|----------|-----------|
| `general` | Общий вопрос | Универсальный ответ + источники |
| `deadline` | Дедлайны | Приоритет LMS + FAQ, без переноса сроков |
| `difficulty` | Сложность | Разбиение на шаги, пререквизиты, поддержка |
| `recommendation` | Рекомендации | Материалы курса + открытые ресурсы по уровню |

## 4. Адаптация уровня

- **beginner** — простой язык, короткие шаги, меньше жаргона.
- **advanced** — термины, асимптотика, ссылки на углублённые разделы.

Параметр передаётся в UI и подставляется в системный промпт.

## 5. Few-shot

Файл `data/few_shot/examples.json` содержит:

- корректные ответы (эталоны);
- некорректные ответы с пояснением, почему они плохие.

Блок few-shot добавляется к системному промпту (функция `format_few_shot_block`).

## 6. RAG-схема

```
data/knowledge/**/*.md
        │
        ▼
  парсинг метаданных
  (module, topic, resource_type, level)
        │
        ▼
  RecursiveCharacterTextSplitter
  (chunk_size=800, overlap=120)
        │
        ▼
  OpenAIEmbeddings (text-embedding-3-small)
        │
        ▼
  Chroma (локально, ./chroma_db)
        │
        ▼
  similarity_search + фильтры метаданных
        │
        ▼
  контекст → LLM (gpt-4o-mini) + LMS-контекст
```

### Метаданные документа

- `module` — номер/код модуля
- `topic` — тема
- `resource_type` — `lecture` | `methodic` | `faq`
- `level` — `beginner` | `advanced`
- `source` — имя файла

### LMS-контур (заглушка)

`src/lms_stub.py` читает:

- `data/lms/schedule.json` — расписание модулей и офис-часов;
- `data/lms/assignments.csv` — задания и дедлайны.

Имитирует API-выгрузку методом `export_json()`.

## 7. Логирование и аналитика

Каждый запрос пишется в `data/analytics/queries.jsonl`:

```json
{
  "timestamp": "...",
  "question": "...",
  "scenario": "deadline",
  "level": "beginner",
  "module": "M1",
  "resource_type": "faq",
  "sources": ["course_faq.md"],
  "answer_preview": "..."
}
```

Дашборд в Streamlit агрегирует:

- запросы по сценариям;
- распределение по уровню;
- нагрузку по модулям;
- журнал для методического разбора.

## 8. Поток одного запроса

1. Студент задаёт вопрос + выбирает уровень/сценарий/фильтры.
2. RAG ищет релевантные чанки (с метаданными).
3. LMS-заглушка добавляет расписание/дедлайны при необходимости.
4. Собирается system + user prompt (с few-shot).
5. LLM генерирует ответ со ссылками на источники.
6. Запрос логируется для аналитики.
